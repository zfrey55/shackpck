  layout, `robots.ts`, `sitemap.ts` and `StructuredData.tsx`, so the `<title>`,

- **[CLOSED `2a85c06`] Canonical URLs.** `alternates: { canonical: './' }`

  (`/repacks?line=`, `/checklist?customer=`) collapse onto the clean URL.

  **[corrected]** The 2026-09-18 note implied this costs a refactor everywhere.
  It does not: `/repacks`, `/checklist`, `/contact` and `/policy` are already

- **TRAP for phase 2:** `openGraph` is inherited as a whole object. When a page

## Sitemap & robots

- **[CLOSED `f0b7cf3`] `app/robots.ts`.** Allow all, `Disallow: /api/` only,
  absolute sitemap pointer. Nothing else is disallowed, by design: `/build` is
  the most-linked internal route after `/` and should rank, and the auth-gated
  routes need **noindex, not Disallow** — a disallowed URL is never fetched, so
  a noindex on it is never seen. noindex for `/admin`, `/account`,
  `/my-builds`, `/checkout` and `/auth/*` is phase 2. No AI crawler is blocked.
- **[CLOSED `2cde71d`] `app/sitemap.ts`.** Six static routes plus one entry per
  `isActive` series, built at deploy time with no `revalidate` — the file is
  frozen until the next build, which is fine because content changes ship as
  deploys. `export const revalidate = 3600` is the lever if that changes. The
  DB read is wrapped in a try/catch with a 10s timeout and a `console.warn`, so
  a build never fails over a sitemap and a `DATABASE_URL` scoped to the Netlify
  runtime instead of the build does not masquerade as success. Verified both
  ways against the dev database and against an unreachable one.
- `/series` is **excluded** from the sitemap: the index filters on
  `isFeatured === true` and no row sets it, so the page renders an empty list.
  See `15-backlog.md`.
- **[CLOSED `88c7be7`] `/checklist/customer/*` is noindex**, via
  `app/checklist/customer/layout.tsx`. The tag rides in a layout because the
  page is a client component and cannot export `metadata`.
- **[CLOSED `7e69f69`] `public/llms.txt`**, llmstxt.org format.

## Server-rendered content — the largest remaining gap

Measured on prod 2026-09-19, visible text in the served HTML:

| Route | Chars | What a crawler gets |
|---|---|---|
| `/policy` | 4,788 | the whole page |
| `/` | 2,836 | hero and pack grid; only "Loading featured series…" is client |
| `/contact` | 443 | the whole page |
| `/checklist` | 347 | **nav, footer, "Loading…"** |
| `/repacks` | 327 | **nav, footer, "Loading…"** |
| `/series` | 336 | **nav, footer, "Loading…"** |

The cause on `/repacks` and `/checklist` is **not** data fetching — both read
local modules (`lib/repack-catalog.ts`, `lib/product-lines.ts`) available at
build time. Their clients call `useSearchParams()` for tab state, which makes
Next 14 prerender the Suspense *fallback* and defer everything else to the
browser. Fixing this means moving the `?line=` / `?customer=` tab state off
`useSearchParams` or restructuring the Suspense boundaries. It is the biggest
SEO win available and the riskiest change in the area; it touches the checklist
page optimised in `f14a057`. Phase 3, own commit.

## Soft 404s — unbounded crawlable URL space

There is no `app/not-found.tsx` and no page calls `notFound()`. Both verified
live on prod 2026-09-19:

- `/series/made-up-slug-xyz` → **HTTP 200**
- `/checklist/customer/totally-made-up-xyz123` → **HTTP 200**, and the page
  title-cases the invented slug into its `<h1>`, presenting a customer that
  does not exist as real.

Any URL under those two prefixes returns 200 forever, so one scraped or
mistyped link seeds an infinite crawl space. The noindex above keeps the
customer half out of the index; `notFound()` on unresolved slugs is the actual
fix and needs server-side slug resolution, so it rides with the `/series/[slug]`
split in phase 2.

## Placeholder routes — removed

**[CLOSED `81befc7`]** `/shop`, `/shop/{gold,silver,rare}` and
`/product/{2024-gold-eagle-1oz,2023-silver-maple-1oz,1907-st-gaudens}` were
live 200s serving a hardcoded sample array with invented prices ($2,423
"American Gold Eagle", $2,199 "Gold Proof Coin") over Unsplash stock photos.
Both dynamic routes ignored their own params, so every category and every slug
rendered the identical fake product. They were orphaned — nothing linked to
them — and Search Console reported every URL "unknown to Google", so a plain
delete was enough and no 410 rules were needed. `components/ProductCard.tsx`
and `components/ProductGallery.tsx` went with them.

**[CLOSED `95f0633`]** The `(site)` route group is gone. `(site)/page.tsx` was
`export { default } from '../page'`, so both it and `app/page.tsx` mapped to
`/` in `app-path-routes-manifest.json`. Next 14 accepted the collision with no
error and no warning and resolved it in favour of `app/page.tsx`.

## Image optimization

- **[CLOSED `1418d91`] `images.unoptimized: true` is gone.**
  `@netlify/plugin-nextjs` v5 redirects `/_next/image` to `/.netlify/images`
  whenever `images.loader` is `default`, which is this site's case.
  `remotePatterns` is the single allow-listed host `images.unsplash.com`.
- **[CLOSED `33722d1`] The favicon was 1254x1254 and 1.9 MB**, served on every
  page as icon, shortcut and apple-touch-icon. Now 192x192 at 43.3 KB. 192
  rather than 512 because no image quantizer is available on the build host —
  sips' 24-bit output puts 512 at 334 KB — and 192 is the real ceiling for this
  file's consumers (Google wants a square multiple of 48px, Apple downsamples
  to 180, and only a web app manifest would want 512; there is none). Same
  filename, so returning visitors keep the cached 1.9 MB copy until it expires.
- **[still true] Pack art is local PNG** in `public/images/packs/` — 83 files,
  ~188 MB tracked, paid on every clone, CI checkout and build. Delivered bytes
  are fine; the **sources** are the problem. See `15-backlog.md` §13.
- **[still true] The home hero is a remote Unsplash URL** (`app/page.tsx:18`),
  the only remote image the site renders.
